## 2. 必須の納品フロー

実行タスクは、対象日と実行IDを一意に決定し、専用の作業ディレクトリだけで4成果物を作成する。最終監査が合格した後に `prepare_delivery_package.py` が同一実行の4点だけをコピーしてマニフェストとSHA-256を作成する。添付直前には `validate_delivery_package.py` が、マニフェスト、4点のファイル名と順序、実行ID、対象日、実ハッシュ、許可外ファイルの不在を再照合する。

検証器が返した `attachments` 配列以外から添付してはならない。ワークディレクトリ、過去実行、Downloads、ファイル更新時刻、ワイルドカードを添付元に用いることは禁止した。

## 4. フェイルクローズ動作

以下のいずれかが起きた場合、完成版4点の自動納品は停止する。

| 停止条件 | 実行結果 |
|---|---|
| 4点のいずれかが欠ける、または許可外ファイルが混在する | 配信パッケージ化または添付直前検証が失敗する。 |
| 添付候補のSHA-256がマニフェストと異なる | 添付直前検証が失敗する。 |
| 最終監査JSONが不合格、未実施、または成果物より古い | 配信パッケージ化が失敗する。 |
| 実行IDまたは対象日がマニフェストと異なる | 添付直前検証が失敗する。 |
| 既存定期タスクを特定できない | 新規の本番タスクを作成・有効化せず、重複実行を回避する。 |

## 5. 定期タスクの状態と残る必須作業

定期実行一覧の照会は、この実行環境では `ref_session_uid` 不足により失敗した。加えて、管理画面のSandboxブラウザは未ログインであり、既存の01:10タスクのID、現在のcron、タイムゾーン、実行指示、稼働状態を読み取れていない。

したがって、**既存定期タスクを変更・有効化したとは扱わない**。重複した本番タスクも作成していない。既存タスクを特定できた後、次の受入条件を満たす更新だけを行う。

1. 既存タスクのIDと重複の有無を記録する。
2. 実行時刻を `01:10 Asia/Tokyo` とし、設定UIまたはCLIのタイムゾーン表示と照合する。
3. 実行モードを新規独立タスクとし、共有の `暗号通貨市況レポート_定期実行プロンプト.md` を唯一の指示として参照させる。
4. マニフェスト作成・添付直前検証・失敗時の未完了報告を必須化する。
5. 更新後にタスク設定のスクリーンショットまたはCLI結果で、時刻、タイムゾーン、実行指示、状態を記録する。
