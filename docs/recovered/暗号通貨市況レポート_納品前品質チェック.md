# 暗号通貨市況レポート：納品前品質チェック

## 目的と適用範囲

このチェックリストは、日次の**完成版4点**、すなわち①X投稿・前編、②X投稿・後編、③16:9インフォグラフィック、④#ETH/#USDC（Base）APR実画面スクリーンショットを納品する直前に必ず実施する品質ゲートである。対象日は、実行開始時のAsia/Tokyoから暦日で1日を引いて算出した単一の `target_date_jst` と `weekday_jp` を用いる。

> **判定原則**：必須項目に不合格、未確認、または根拠不一致が1件でも残る場合、完成版4点として納品してはならない。確認済みの部分だけを、取得不能項目・エラー状態・限界を明記した未完了／再取得待ちとして報告する。
>
> **X投稿の文字数方針**：Premium長文投稿を前提とし、標準280文字を含む任意の文字数上限は日次品質ゲートに適用しない。文字数ではなく、固定構成、役割分離、根拠、数値整合性、可読性を確認する。

## インフォグラフィック視覚ゲート

画像全体を確認用プレビューだけで済ませず、必要に応じて主要4パネルと下部LP帯を拡大して確認する。次の項目は、すべて**目視確認が必須**である。

| 領域 | 必須確認項目 | 合格基準 |
|---|---|---|
| ヘッダー・フッター | 日付・曜日・副見出し・取得時刻・USD/JPY・出典 | 文字化け、切れ、重なり、誤記がなく、日次JSONと監査台帳に一致する |
| パネル1：主要暗号通貨の価格 | #BTC・#ETH・#BNB、USD、日本円換算、24時間比、矢印 | 日本円換算と24時間比が別列。見出し「24時間比」はパネル内で1回だけ。数値・文字・罫線が重ならない |
| パネル2：市場概況 | Fear & Greed、半円ゲージ、時価総額、24時間取引高、#BTC・#ETHドミナンス | Fear & Greed見出しと半円ゲージに視覚的な重なりがない。右側の4指標は各々「ラベル＋数値」の1行で、罫線・アイコン・文字が重ならない |
| パネル3：Baseチェーンの状況 | Base TVL、Base 24時間DEX出来高、#USDCドミナンス、変化率 | 上部の列見出しを「24時間比」とし、Base TVL行は矢印と数値だけを表示する。文字・円換算・変化率・罫線が重ならない |
| パネル4：#ETH/#USDC LP確認 | Base 0.05%／0.3%の名称、APR、TVL、24時間出来高 | 各水色ボックス内に2行で完全に収まり、左右・上下の内側余白が確保される。枠外へのはみ出し、文字同士の重なりがない |
| 下部LP帯 | #ETHの方向に沿った確認文 | 中央太字、標準60px（最小48px）で可読性を確保する。帯の端・盾アイコン・上昇アイコンと重ならず、個別LPの結果を断定しない |

## X投稿の主要指標書式ゲート

【主要指標】と【主要指標（詳細）】は、投稿本文にそのまま貼り付けられるテキストであることを確認する。監査時は、各見出しの開始から次の見出しまでを対象に、Markdown表・HTML表・罫線表・`|`・列見出し・タブ揃えがないことを確認する。

**前編の必須行順**は「市場全体 → #BTC → #ETH → #BNB → 市場心理（確認済みの場合） → ドミナンス（確認済みの場合） → 出典・取得時刻」とする。市場全体、#BTC、#ETH、#BNBは、取得不能であっても行を省略せず、理由を併記する。

**後編の必須行順**は「国内2社のAPI取得参考値 → 国内2社合計 → UniswapまたはBase上DEX → 国内2社とDEXの比較 → Baseチェーン → #ETH/#USDC（Base）参考 → 出典・取得時刻」とする。国内2社、DEX、比較、Base、APRのいずれかが取得不能または比較不能なら、該当行を残して理由を記す。比較不能時に倍率・市場規模評価・優劣を書かない。

全ての行は `・項目名：値｜補足` のように、1行で独立して読める文にする。複数の数値を並べる場合は全角縦線 `｜` または読点を使い、Markdown表の区切り記号である半角 `|` を使わない。USD（JPY）併記、24時間比、出典・取得時刻、未確認時の理由、比率計算の分子・分母といった内容上の既存要件は、表形式を廃しても緩和しない。

## 数値・表記ゲートの詳細

| 項目 | 必須判定 |
|---|---|
| 価格・市場規模 | USD（JPY）併記。円換算は実行時取得のUSD/JPYを使い、本文・画像・監査台帳で一致させる |
| 変化率 | CoinMarketCap由来の変化率は「24時間比」と表記する。#BTC・#ETHの上昇は緑上向き、下落は赤下向き、未確認時は矢印なし |
| 取得不能値 | 推測せず「未確認」または取得不能理由・限界を記す |
| ニュース | 媒体名、URL、タイトル、掲載日時、原典または裏取り、本文表現、取得時刻、採否理由を監査台帳に記録する |
| 因果表現 | 事実と価格因果を混同せず、価格因果は「可能性」「意識された可能性」「因果は未確認」等で限定する |
| APR | 実画面の表示値を、当日撮影時のものとして扱う。画像内のAPR・TVL・出来高を日次レポート本文・画像へ転記する場合は、画面と照合する |

## 不合格時の扱い

| 不合格の種類 | 必須対応 |
|---|---|
| 数値・日付・出典の不一致 | 原データから再取得・再計算し、監査台帳と全成果物を再照合する |
| 文字の重なり・はみ出し・読みにくさ | 固定レンダラーを修正し、再描画後に機械検証と目視検査をやり直す。固定意匠の変更はユーザーの明示承認を得る |
| APR画面の不備 | 定められた再試行条件の範囲で再取得する。なお不備が残る場合は完成版4点として納品しない |
| 根拠不足・検証不能 | 推測による補完をせず、未完了／再取得待ちとして限界を明記して報告する |

## 監査台帳への記録

各日次レポートの監査台帳には、少なくとも次を追記する。

1. 品質ゲート1〜7の実施時刻、担当成果物、合否。
2. インフォグラフィック視覚ゲートの確認結果（各パネル、LP帯、フッター）。
3. 不合格が生じた場合の原因、修正内容、再検査結果。
4. 完成版として納品した場合は、4点がすべて合格した旨、最終確認時刻、`run_id`、`final_audit_YYYYMMDD.json` の合格件数、配信マニフェストのパス・SHA-256、完成版4点のSHA-256。

自動納品時は、共有の `暗号通貨市況レポート_自動納品契約.md` に定める実行ID・出力隔離・マニフェスト限定添付・停止条件を、この第7ゲートの必須条件として適用する。
