# cron-job.org による daily.yml 起動手順（GitHub scheduledイベント不達の恒久対策）

## 背景・目的

GitHub Actionsの`schedule`イベントが5日連続で配信されず、毎朝の手動実行（`workflow_dispatch`）が必要な状態が続いています。実行分を30→37分へ変更しても改善しませんでした。

対策として、外部サービス**cron-job.org**から毎日決まった時刻にGitHubの`workflow_dispatch` APIを直接呼び出し、`daily.yml`を強制的に起動します。VPSを使わないのは、SSH作業や環境差異の往復を避け、ブラウザだけで完結させるためです。

**GitHub側の`schedule`トリガーは削除しません。** `.github/workflows/daily.yml`の`on.schedule`はそのまま残し、cron-job.orgをメインの起動経路、GitHub側のscheduledイベントをフォールバック（たまたま配信された場合の保険）として併存させます。両方が同じ日に起動しても、本手順の【3】で説明する冪等性ガードにより二重生成にはなりません。

**この手順書について**：本手順の①GitHub側の手順は、GitHub公式ドキュメントの現在のソース（github/docsリポジトリ）を直接確認して作成しています。②cron-job.org側の手順は、本セッションの実行環境からcron-job.org・docs.cron-job.orgへの直接アクセスがネットワークポリシーにより遮断されており（`docs.github.com`も含め、確認済み）、検索結果からの間接的な裏付けに基づいています。cron-job.orgの実際の画面が本書の記載と異なる場合は、見えている項目名をそのまま使えば問題ありません（項目の「役割」で説明している箇所はその旨を明記しました）。もし大きく違う場合は私（Claude）へ画面の様子を伝えていただければ、手順を修正します。

## 1. GitHub fine-grained PAT（個人アクセストークン）の発行

対象リポジトリ`crypto-daily-brief`のみに限定し、`Actions`権限のみを`Read and write`にしたトークンを発行します。

1. GitHubに自分のアカウントでログインした状態で、右上のプロフィールアイコンをクリックし、**Settings** を選ぶ。
2. 左側メニューの一番下の方にある **Developer settings** をクリック。
3. 左側メニューの **Personal access tokens** の下にある **Fine-grained tokens** をクリック。
4. 右上（または画面上部）の **Generate new token** ボタンをクリック。
5. **Token name**：トークンの名前を入力する欄。分かりやすい名前（例：`cron-job-org-daily-dispatch`）を入力する。
6. **Expiration**（有効期限）：**90 days** を選択する。選択肢に90日が無い場合は、日数を入力する形式（1〜366の整数、または「no expiration」＝無期限）になっているので、`90`と入力する。**無期限は選ばない**（オーナー指定どおり90日で運用し、期限が来たら【4】の手順で再発行する）。
7. **Description**（任意）：省略可。トークンの用途をメモしておきたい場合は記入する。
8. **Resource owner**：自分のアカウント（`MFlab-inc`）を選ぶ。組織の選択肢が表示された場合も、`MFlab-inc`自身のアカウントを選べば問題ない。
9. **Repository access**：**Only select repositories** を選ぶ（「All repositories」や「Public repositories」は選ばない）。
10. 選択後に表示される **Selected repositories**（または「Select repositories」）というリポジトリ選択欄で、`crypto-daily-brief` を検索して選ぶ。**これ以外のリポジトリは追加しない。**
11. **Permissions** セクションまでスクロールする。**Repository permissions** の見出しの右側に展開用のアイコン（小さな矢印・「Expand」）があればクリックし、権限の一覧を開く。
12. 権限一覧の中から **Actions** の行を探し、右側のプルダウンで **Read and write** を選ぶ（既定は「No access」になっている）。**Actions以外の権限はすべて「No access」のままにする。**
13. ページ最下部までスクロールし、**Generate token** ボタンをクリックする。確認画面が出た場合は、もう一度 **Generate token** をクリックする。

トークンが緑色の帯で1回だけ表示されます。**この画面を離れると二度と表示されません。** 次の【2】ですぐに使うので、コピーしてから作業を進めてください（テキストファイル等へ保存する場合も、Gitリポジトリにはコミットしないこと）。

## 2. cron-job.org のアカウント作成とジョブ設定

### 2-1. アカウント作成

1. https://cron-job.org を開き、**Sign up**（新規登録）からメールアドレスとパスワードでアカウントを作成する。
2. 登録したメールアドレスに確認メールが届くので、本文中のリンクをクリックして本登録を完了させる。
3. https://console.cron-job.org でログインする。

### 2-2. ジョブ（cronjob）の作成

ログイン後のダッシュボードで **CREATE CRONJOB**（新規ジョブ作成）ボタンをクリックし、以下を設定します。

**基本情報**
- **Title**（タイトル）：自分が分かる名前を入力（例：`crypto-daily-brief daily dispatch`）。
- **URL**（実行先URL。画面によっては「Address」と表示される場合あり）：以下を**そのまま**入力する。

  ```
  https://api.github.com/repos/MFlab-inc/crypto-daily-brief/actions/workflows/daily.yml/dispatches
  ```

**リクエストの方法・ヘッダー・本文**

「Method and Headers」というタブ（画面によって呼び方が異なる場合あり。HTTPメソッドとヘッダーをまとめて設定する箇所を探す）を開き、以下を設定する。

- **HTTPメソッド**：プルダウンから **POST** を選ぶ。
- **リクエストヘッダー**：ヘッダーを追加できる欄に、以下の4つを1行ずつ（名前と値のペアで）追加する。

  | ヘッダー名 | 値 |
  |---|---|
  | `Authorization` | `Bearer <【1】で発行したPATの値>` |
  | `Accept` | `application/vnd.github+json` |
  | `X-GitHub-Api-Version` | `2022-11-28` |
  | `Content-Type` | `application/json` |

  ※`Authorization`の値は、`Bearer `（半角スペース含む）に続けて【1】で発行したトークン（`github_pat_`で始まる長い文字列）をそのまま貼り付ける。

- **リクエスト本文（Body）**：POSTを選ぶと本文を入力する欄が表示される。以下をそのまま入力する。

  ```json
  {"ref": "claude/crypto-daily-brief-launch-jo6yki"}
  ```

**実行スケジュール**

「Schedule」タブ（実行スケジュール設定）を開き、毎日07:37（日本時間）に実行されるよう設定する。

- cron-job.orgにはタイムゾーンの設定があります（アカウント設定内、または各ジョブのスケジュール設定内のいずれか。画面を確認してください）。
- **一番確実な方法**：タイムゾーンを「UTC」に設定できる場合は、UTCを選んだ上で毎日 **22:37** に実行されるよう設定する（22:37 UTC = 07:37 JST）。
- タイムゾーンを日本時間（Asia/Tokyo）に設定できる場合は、毎日 **07:37** に実行されるよう設定してもよい（結果は同じ）。
- どちらのタイムゾーンで設定したか分からなくなった場合は、【3】の動作確認で実際の実行時刻を確認して調整してください。

**通知設定**

「Notifications」タブ（通知設定。無い場合はアカウント全体の設定内にある可能性あり）を開き、失敗時にメール通知を受け取る設定（"Notify on failure" 等の名称）を**有効化**する。

設定が終わったら、保存（**Create**または**Save**というボタン）をクリックしてジョブを登録する。

## 3. 動作確認

### 3-1. cron-job.org側でテスト実行する

作成したジョブの一覧画面（または詳細画面）に、今すぐ1回だけ実行するボタン（実行・再生アイコン、または「Run now」「Test run」といった名称）があります。これをクリックして手動でテスト実行してください。

実行後、そのジョブの実行履歴（History / Execution history）に、HTTPステータスコードが記録されます。**`204`（成功）であれば正常です。** `401`が出た場合はPATの値やヘッダー名を、`404`が出た場合はURLのスペルを確認してください。

### 3-2. GitHub側のActionsタブで起動を確認する

1. https://github.com/MFlab-inc/crypto-daily-brief を開き、上部の **Actions** タブをクリックする。
2. 左側のワークフロー一覧から **daily-crypto-brief** を選ぶ。
3. 実行履歴の一覧に新しい実行が追加されているはずです。各行の起動理由（トリガー）が **workflow_dispatch** と表示されていれば、cron-job.orgから正しく起動できたことが確認できます（GitHub側の`schedule`で自動起動した場合は**schedule**と表示されるため、区別できます）。
4. 実行行をクリックすると、進行状況・成功／失敗を確認できます。

### 3-3.（補足）GitHub自身の手動実行ボタンでも確認できる

上記3-2と同じActionsタブの**daily-crypto-brief**画面で、右上に **Run workflow** というボタンがあります。これはcron-job.orgを経由せず、GitHub上で直接ワークフローを起動する機能です。ブランチを選んで実行すれば、cron-job.orgを介さずに`daily.yml`自体が正常に動くかどうかを切り分けて確認できます。cron-job.org側だけがうまくいかない場合の切り分けに使ってください。

### 3-4. 冪等性ガードにより二重生成にならないことについて

`daily.yml`には、対象日（実行時点のJSTで前日）の成果物が既に存在するかどうかを最初に判定するステップがあります（`実行要否を判定`というステップ名）。

- フェーズ1（データ取得・図版）は、対象日の`final_audit_*.json`が既に存在すれば、それ以降の処理（取得・描画・撮影・監査・コミット）をすべてスキップします。
- フェーズ2（本文生成）は、対象日のPASS済み下書き（`post_audit_*.json`にPASSの記録あり）が既に存在すれば、以降の処理をすべてスキップします。

このため、たとえば**cron-job.orgが07:37に起動して正常に投稿を生成した後、GitHub側の`schedule`が同じ日にたまたま配信されても**、後から起動した実行は「既に成果物がある」と判定してほぼ何もせず終了します。二重に投稿が生成されたり、コミットが競合したりすることはありません。

## 4. トークンの有効期限が切れた場合

### 4-1. どう気づくか

以下のいずれかで気づきます。

- **cron-job.orgからの失敗通知メール**（【2】で有効化した通知）。GitHubのAPIは、期限切れのトークンで呼び出すと`401 Unauthorized`を返すため、cron-job.org側では「失敗」として記録・通知されます。
- **GitHubからの通知メール**：GitHubはfine-grained PATの有効期限が近づく際・切れた際に、トークンを発行したアカウント宛にメールで知らせます（アカウントの通知設定によります）。
- **cron-job.orgの実行履歴**：ジョブの実行履歴を開くと、HTTPステータスコードが`401`になっている実行が確認できます。
- **outputsの更新が止まる**：上記に気づかなかった場合でも、リポジトリに毎朝コミットされるはずの`daily: YYYY-MM-DD (shadow)`や`post-draft: YYYY-MM-DD (auto)`が増えなくなっている（またはGitHub側の`schedule`フォールバックだけがまれに動いた分しか増えていない）ことで気づけます。

### 4-2. 対処（再発行と差し替え）

1. 本手順書の【1】と同じ手順で、新しいfine-grained PATを発行する（設定内容は同じ：対象リポジトリ`crypto-daily-brief`のみ、`Actions`権限を`Read and write`、有効期限90日）。
2. cron-job.orgの管理画面で、【2-2】で作成したジョブを開き、リクエストヘッダーの`Authorization`の値を、新しいトークンの値に**書き換える**（`Bearer `に続けて新しいトークンを貼り付け直す）。ジョブ自体を作り直す必要はない。
3. 変更を保存し、【3-1】の要領で一度テスト実行し、`204`が返ることを確認する。
4. 期限切れになった古いトークンは、GitHubの **Fine-grained tokens** の一覧画面から削除してよい（自動的に無効化されているが、一覧の整理のため）。
