# インフォグラフィック意匠 変更履歴

`scripts/infographic_renderer.py` の固定意匠に対する変更を記録する。
統合運用基準 §5 は固定意匠の変更にオーナーの明示承認を要求するため、
承認のない変更を行ってはならない。`docs/recovered/` の原本は変更しない
（v1.0 の凍結参照物として保全する）。

## v1.3 — 2026-08-12（オーナー承認済み）

**承認**：2026-08-12・オーナーによる明示承認。
**適用範囲**：`scripts/capture_apr.py`。図版意匠（v1.1凍結）には触れていない。
**不変**：待機時間（3秒／8秒／間3秒）、再試行回数（最大3回）、
クロップ式、ビューポート、検知の意図（TODAY値の欠落検出）、
ゲートの合格条件、フェイルクローズ。

| 内容 | 変更ファイル |
|---|---|
| APR検知文字列を `"N/A% TODAY"` → `"N/A%"` へ短縮。カードのDOMが `<div class="apr-value">N/A<span>%</span></div><span class="apr-label">TODAY</span>` と分かれており、描画テキストが `N/A%\nTODAY`（間に改行）になるため、**原版から一度も一致していなかった**。検知器の修理であり、検知の意図は不変 | `capture_apr.py` |

### 検証

実カードと同一構造のDOMで実測。

| ケース | 旧 `"N/A% TODAY"` | 新 `"N/A%"` |
|---|---:|---:|
| 正常（6カードとも値あり） | 0 | **0**（誤検知なし） |
| 1カードのみ N/A | 0 | **1**（検知） |
| 全6カード N/A | 0 | **6**（検知） |

旧文字列は全ケースで0、すなわち検知機能なし。新文字列は正常時に誤検知せず、
欠落時のみ件数どおり検知する。`GeckoTerminal取得失敗` 側は v1.2 承認2 で
既に正常化済みで、これによりAPR撮影の異常検知が両系統とも機能する状態になった。

### v1.2 の「未解決」項目について

v1.2 に記載した未解決項目（`N/A% TODAY` が機能しない）は、本 v1.3 で解消。

## v1.2 — 2026-08-12（オーナー承認済み）

**承認**：2026-08-12・オーナーによる明示承認（承認1〜3）。
**適用範囲**：`scripts/capture_apr.py`、`scripts/fetch_data.py`。
**図版意匠には一切触れていない** — v1.1 の凍結は維持される。
**不変**：APR撮影の待機時間（3秒／8秒／間3秒）、再試行回数（最大3回）、
クロップ式 `(8, 130, width-8, min(1050, height-10))`、検知文字列、
Fear & Greed の取得元、検証ゲートの合格条件、フェイルクローズ。

| ID | 内容 | 変更ファイル |
|---|---|---|
| 承認1 | ビューポート高を `1280` → `980` に変更。Selenium の `set_window_size` はブラウザ枠込みの外寸、Playwright の `viewport` は内寸という移植誤差により、`min(1050, height-10)` が原版の 970 ではなく 1050 となり、約80px余計に写っていた。実測で初回実行 1484×920・見本 1484×840。980 にすることで見本と一致し、統合運用基準 §6 の「レンジAPRシミュレーションの文字を含めない」を満たす | `capture_apr.py` |
| 承認2 | N/A・取得失敗の判定対象を `page.content()`（HTMLソース）から `page.inner_text("body")`（描画済みテキスト）へ変更。ソースには `noteEl.textContent = '⚠ GeckoTerminal取得失敗'` という**JSの文字列リテラル**が常に含まれ、正常時も必ず誤検知していた。初回実行ログの `✗ N/A検出（N/A: 0, エラー: 1）` ×3 がこれにあたり、毎回3回空振りして約33秒を空費し、かつ本物の取得失敗を検知できない状態だった | `capture_apr.py` |
| 承認3 | `fetch_cmc` を3エンドポイント個別の try/except に分離。従来は1関数で直列に呼んでいたため、1本の失敗が価格・時価総額まで巻き添えにして全項目「未確認」になっていた。区画ごとに取得し、失敗した区画のみ「未確認」に落とす。取得元・推測で埋めない方針・ゲート・フェイルクローズは不変 | `fetch_data.py` |

### 検証

スタブによる区画別障害試験で、`quotes` / `global-metrics` / `fear-and-greed`
のいずれか1本が失敗しても残り2本が生き残ることを確認（承認3）。
4シナリオ（全成功・F&G失敗・global失敗・quotes失敗）すべてで
`final_audit` は `overall: PASS / failed: 0`。

### 未解決だった項目（→ v1.3 で解消）

- **`N/A% TODAY` の検知は承認2の後も機能しない。** カード内の DOM が
  `<div class="apr-value">N/A<span>%</span></div><span class="apr-label">TODAY</span>`
  と分かれており、描画テキストは `N/A%\nTODAY`（間に改行）になる。
  実測でも `page.content()` / `inner_text()` の双方で一致数 0。
  つまり原版から一度も機能していない。承認2は「検知条件は不変」との
  指示のため文字列は変更していない。
  **→ 2026-08-12 に `N/A%` への短縮が承認され、v1.3 で解消。**

### 基準文書に対する改定点

本改定は統合運用基準の以下2点を実質的に改める。`docs/recovered/` の原本は
凍結参照物のため書き換えず、差分を本節に記録する。

- **§1（`#` 付与）**：「通貨名には `#` を付ける」を、
  **「X投稿本文では `#` 付与を維持し、画像内では `#` を付けない」** に改める（B-3）。
- **§5 / §4（LP確認文の表示先）**：固定意匠に含まれていた画像下部のLP確認帯を
  **ヘッドライン帯**に用途変更し、LP確認文の表示先を
  **画像からX投稿後編【LP運用者向けに一言】へ移す**（B-1・B-2）。
  §4 の条件分岐ルール（#ETH上昇なら#USDC偏り・上限側レンジ外・反落耐性を確認、等）自体は不変。

### 検証

スタブ値による試走で、通常系・全項目未確認系の双方について
`final_audit` が `overall: PASS / failed: 0`（C1〜C10）であることを確認済み。
実データによる検証は初回 `workflow_dispatch` 実行で行う。
