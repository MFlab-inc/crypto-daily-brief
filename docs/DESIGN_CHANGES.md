### A. ヘッドライン差し込みワークフロー（最優先）

新規 `.github/workflows/set_headline.yml`。`workflow_dispatch` のみ（cronなし）。

| 入力 | 内容 |
|---|---|
| `target_date` | 省略可。省略時は実行時JSTの前日 |
| `headline` | 必須。図版下部帯（`summary`）に差し込む本文 |

**処理**：`outputs/{target_date}/daily_data.json` の `summary` を上書き →
`scripts/infographic_renderer.py`（無変更）で `infographic.png` を再描画 →
`scripts/verify_data.py`（無変更）を再実行 → PASS時のみ
`daily_data.json` / `infographic.png` / `final_audit_*.json` の3ファイルだけを
コミット。`raw_data.json` ・`apr_screenshot.jpg` ・`run_context.env` は触れない。
冪等性ガード（`daily.yml` 側のもの）は本ワークフローの対象外。

**設計判断（記録）**

- **`headline` は必ず `env:` 経由でのみ渡し、`run:` 内で `${{ inputs.headline }}`
  を直接展開しない。** 自由入力文字列を `${{ }}` でシェルスクリプトへ直接埋め込むと
  テンプレートインジェクション（シェルコマンド注入）の既知のリスクがあるため、
  `env: HEADLINE: ${{ inputs.headline }}` と渡し、Python側は `os.environ["HEADLINE"]`
  としてのみ読む。`target_date` も同様に `env:` 経由。
- **`target_date` はワークフロー先頭で `^[0-9]{4}-[0-9]{2}-[0-9]{2}$` の正規表現検証を
  必須にし、以降はこの検証済み値だけを使う。** 未検証のままだとパス
  （`outputs/{target_date}/...`）に直接使われるため、ディレクトリトラバーサル等の
  リスクを形式検証だけで機械的に排除する。
- **`headline` が空文字（または空白のみ）の場合はエラー終了し、`daily_data.json` を
  一切変更しない。** プレースホルダーのままコミットさせない、というオーナー指示を
  Python側の明示チェックで担保する（GitHub側の `required: true` はUI上の必須表示に
  すぎず、API直叩きでは空文字を防げないため）。
- **`verify_data.py` の再実行時のみ `--skip-date-check` を付ける。** このフラグは
  `verify_data.py` 自身のdocstringに「過去日の再検証用」と明記された既存機能で、
  今回新設したものではない。本ワークフローは実行日と無関係に任意の過去日を
  対象にできる設計のため、C3（対象日=実行前日）は本来 `daily-crypto-brief`
  専用の時刻整合チェックであり、ここでは意味を持たない。C1・C2・C4〜C11は
  従来どおり全て実行される（禁止語・二重括弧チェックのC5も含むため、
  ヘッドラインに禁止語が入っていれば監査でFAILし、コミットされない
  ——実際に「仮想通貨」を含むヘッドラインでFAIL・exit 1・無変更を確認済み）。
- **`concurrency.group` を `daily-crypto-brief` として `daily.yml` と共有。**
  両ワークフローとも同じブランチへpushするため、直列化してpush競合を防ぐ。
- **CJKフォント（`fonts-noto-cjk`）は `daily.yml` と同様にインストールする。**
  再描画はレンダラーを直接呼ぶため、フォント未導入だと日本語が文字化けした
  画像が「監査PASS」のまま残ってしまう（C10は画像サイズしか見ない）。
  一方 Playwright／APR撮影は行わないため、そのインストールは省略している。

### C. APR変化の要因分解（改善②）

`lp.pools[]` の各エントリに `change_vs_prev` を追加。前日 `outputs/{前日}/daily_data.json`
を読み、APR・24時間出来高・TVLそれぞれの相対変化率（`(当日-前日)/前日×100`）を算出する。
**算術的分解のみ。原因の解釈・推測は行わない。**

```json
"change_vs_prev": {
  "apr_change": "+23.43%",
  "volume_24h_change": "+12.50%",
  "tvl_change": "+10.89%"
}
```

3指標は互いに独立して縮退する（例: 前日のTVLだけ未確認でもAPR変化率は算出する）。

| 縮退理由 | 発生条件 |
|---|---|
| `比較不可（前日データなし）` | 前日の `daily_data.json` 自体が存在しない（初日・欠測日） |
| `比較不可（前日値未確認）` | 前日ファイルはあるが、当該指標が `未確認` または前日のプール名が一致しない |
| `比較不可（当日値未確認）` | 当日のGeckoTerminal取得自体が失敗している |

前日TVLが0の場合もゼロ除算を避けて `比較不可（前日値未確認）` に落とす（実運用では
起こらない想定だが防御的に処理）。図版には描画しない。

**ワーディング注意（記録）**：縮退理由の文言に「前日データなし」「前日値未確認」を
そのまま使うと、C5の禁止語チェック対象「前日比」（統合運用基準§1が禁止する
騰落率ラベル）が偶然部分一致するリスクがある。「前日データなし」「前日値未確認」は
いずれも「前日」の直後が「デ」「値」であり「比」ではないため衝突しないことを
文字列レベルで確認済み（実際に監査を通しても衝突しないことをテスト済み）。

### 実装時に検出・修正したバグ（記録）

`fetch_data.py` の `main()` 内で、CMCグローバル指標を保持する変数 `g`
（`g = quotes.get("global")`）と、C実装で追加したループ変数
`for pd, g in zip(pools_built, (g005, g03))` が**同名で衝突**していた。
Pythonは関数スコープのため、このループが `market_cap` 等の組み立てより前に
実行されると `g` が上書きされ、**時価総額・24時間取引高・両ドミナンスが
毎回「未確認」になる**実害あるバグだった。ループ変数を `pool_g` に改名して解消。
テストで市場データが正しく `$2.170兆` 等になることを確認済み。

### コミット前の独立レビュー（多視点・反証検証）で確認・修正した欠陥

仕様準拠・正当性・運用回帰の3視点で独立レビューし、指摘は全件、実コードの
実行による反証検証を経て確定した。確定した実欠陥は1件:

- **C11×表示丸めの不整合（修正済み）**: `combined_usd` を `fmt_m`（$0.01M =
  1万ドル刻み）で表示すると、真値が$1M未満の日は表示丸めだけで±0.5%を超え、
  **正しいデータでC11がFAIL→exit 1→無人実行が停止**することを実行で実証
  （例: 合計93.34 ETH → ratio 1.0053 FAIL。$5,000未満は "$0.00M"→ratio 0 で必ずFAIL）。
  監査の±0.5%（オーナー指定）には触れず、**表示側を修正**: `combined_usd` は
  $2M未満を実額表示（`$189,036`）とし、$2M以上は従来どおり `fmt_m`。これにより
  量子化誤差は全域で±0.5%に対し十分小さくなる（$2M境界で≤0.25%）。あわせて
  C11のゼロ分岐を `combined_eth` の表示量子（0.01 ETH）の半分まで許容する形に
  修正し、真値0.005 ETH未満の極限でも正データが落ちないようにした。
  修正後の再検証: 旧FAIL帯93.34 ETHが ratio 1.0002 でPASS、+3%改ざんと
  ゼロ分岐の真の不整合（$500表示）は引き続きFAIL（ゲート健在）。

通常出来高（数千ETH＝$5M以上）はレビューでも修正前から健全（最悪偏差0.13%）
と確認されており、本修正は縮退日の誤停止防止のみが目的。他の指摘は
レビュー用差分ファイルの生成手順に関するもので、出荷コードへの影響なし。

| 承認3 | `fetch_cmc` を3エンドポイント個別の try/except に分離。従来は1関数で直列に呼んでいたため、1本の失敗が価格・時価総額まで巻き添えにして全項目「未確認」になっていた。区画ごとに取得し、失敗した区画のみ「未確認」に落とす。取得元・推測で埋めない方針・ゲート・フェイルクローズは不変 | `fetch_data.py` |

### 検証

スタブによる区画別障害試験で、`quotes` / `global-metrics` / `fear-and-greed`
のいずれか1本が失敗しても残り2本が生き残ることを確認（承認3）。
4シナリオ（全成功・F&G失敗・global失敗・quotes失敗）すべてで
`final_audit` は `overall: PASS / failed: 0`。

### 未解決だった項目（→ v1.3 で解消）

- **`N/A% TODAY` の検知は承認2の後も機能しない。** カード内の DOM が
  `<div class="apr-value">N/A<span>%</span></div><span class="apr-label">TODAY</span>`
  と分かれており、描画テキストは `N/A%\nTODAY`（間に改行）になる。
  実測でも `page.content()` / `inner_text()` の双方で一致数 0。
  つまり原版から一度も機能していない。承認2は「検知条件は不変」との
  指示のため文字列は変更していない。
  **→ 2026-08-12 に `N/A%` への短縮が承認され、v1.3 で解消。**
