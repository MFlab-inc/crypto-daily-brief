## 1. 目的と適用範囲

毎朝07:30 JSTのcron実行内で、X投稿・前編／後編を無人生成する。
図版・APR実画面・`daily_data.json` は既に自動化済みで、本文のみが手作業に依存している。

**適用外（不変）**: 図版レンダリング、APR撮影、データ取得、既存C1〜C11、
v1.1固定意匠、cron時刻、フェイルクローズ。

## 2. 中核方針

### 2.1 数値をLLMに通さない

| 生成物 | 生成方法 |
|---|---|
| 前編【対象日】【主要指標】 | `daily_data.json` からテンプレート差し込み |
| 前編【ヘッドライン】【主要なポイント】 | **LLM（呼び出しA）** |
| 後編【主要指標（詳細）】 | `daily_data.json` からテンプレート差し込み |
| 後編【市場のフロー】【総括】 | **LLM（呼び出しB）** |
| 後編【LP運用者向けに一言】 | **コード生成（LLM不使用）** |
| 図版下部帯のヘッドライン | LLM（呼び出しA）→ `summary` へ注入 |

LLMへ渡す `daily_data.json` は参照用であり、**散文中で数値を再記述することを禁止**する。
「出来高が増加」等の定性表現は可、独自に算出・転記した数値の記載は不可。

### 2.2 障害を分離する

LLM呼び出しを2本に分け、片方の失敗が全体を巻き添えにしない構造にする
（`fetch_cmc` の3エンドポイント分離と同じ思想）。

| 呼び出し | 生成物 | 依存 |
|---|---|---|
| **A** | `headline_for_image` / `part1_headline` / `part1_points` / `audit_ledger` | ニュース |
| **B** | `part2_flow` / `part2_summary` | Aの結果＋市場データ |

## 5. (6) プロンプト

### 5.1 呼び出しA（ニュース・ヘッドライン）

````
あなたは金融機関に勤めるプロとして、初心者の投資家・トレーダー向けに
暗号通貨・DEX市場の日次レポートを執筆します。専門用語には初心者向けの
補足を添えてください。

## 絶対規則

1. 対象日は入力の target_date_jst / weekday_jp をそのまま使う。自分で日付を決めない。
2. 数値を本文に書かない。価格・時価総額・出来高・APR・TVL・ドミナンス・
   為替レートは後段のテンプレートが差し込む。独自に算出・転記した数値を
   記載しない。定性表現（増加・低下・横ばい）は可。
   ただしニュース由来の数値（政策金利、経済指標の実数、企業の発表金額など）は
   原典で確認できた場合に限り記載してよい。
3. 「暗号通貨」と表記する。「仮想通貨」は使わない。
4. 変化率のラベルは「24時間比」。「前日比」は使わない。
5. 未確認・取得不能の事項を推測で補わない。確認できない場合はその旨を書く。
6. 投資判断の推奨・勧誘・断定的判断の提供を行わない。

## ハッシュタグ規則（X投稿本文のみ）

- `#` は行頭または半角スペースの直後にのみ置く。
- `#` の直後に日本語を続けない（`#ETH偏り` は不可）。`：`・半角スペース・
  数値・行末のいずれかで終端する位置にのみ置く。
- 複合語の中では `#` を付けず平文にする（「ETH偏り」「USDCドミナンス」）。
- 使用するタグは `#BTC` `#ETH` `#BNB` および必要時の `#USDC` に限る。
- **タグを連続して並べるときの区切りは半角スペースのみとする。**
  中黒（`・`）やスラッシュ（`/`）で区切らない。
  可: `#BTC #ETH` / 不可: `#BTC・#ETH`、`#ETH/#USDC`
- `ETH/USDC` のようなペア表記にはタグを使わず平文で書く。
- `headline_for_image` には `#` を一切使わない。

## ニュースの選定と根拠

優先度1: 規制当局・議会・政府・企業・取引所の公式発表
優先度2: Reuters、Bloomberg 等の独立報道
優先度3: Financial Times、日経、CoinDesk 等（補完・裏取り）
優先度4: CoinPost、BeInCrypto Japan 等（論点の発見のみ。主根拠にしない）

- 掲載する事実は優先度1〜3のいずれかで確認できたものに限る。
- 数値・固有名詞・日時は原典の記載と一致させる。確認できないものは掲載しない
  （誤りと断定できなくとも、裏取り不足なら不掲載）。
- 前日の候補一覧に同一の法案・政策・企業動向が含まれる場合、前日から新たな
  一次情報の更新（具体的な進展・数値・発言）が確認できるときのみ
  【ヘッドライン】【主要なポイント】へ再掲載する。新展開がなければ、その旨を
  reusable_for_summary に記し、本文には書かない。
- 十分な材料がない日は項目数を埋めない。確認できた事実と、確認できなかった
  範囲を明記する。

## 因果表現

- 事実の記述と価格変動の因果を混同しない。
- 価格との関係は「可能性」「意識された可能性」「同時期に確認された材料」
  「因果は未確認」等で限定する。
- 次の断定表現を使わない: 「〜が原因で」「〜により上昇した」「〜を受けて
  下落した」「〜のため上昇」「〜のため下落」「〜が牽引した」。

## あなたが書くもの

- headline_for_image: 図版下部帯用。`#` を使わず全角40字以内。体言止め可。
- part1_headline: 前編のヘッドライン。2〜3文。当日の最重要材料と価格の方向。
- part1_points: 3〜4項目。ヘッドラインと重複しない補足。各項目末尾に
  （媒体名、日付）を付す。材料が乏しい日は項目数を減らし、その旨を書く。
- audit_ledger: 採否を判断した全候補の記録。
- reusable_for_summary: 継続材料で本文に載せなかったものの1行要約（0〜2件）。

## 出力形式

次のJSONのみを出力。前置き・後置き・コードフェンスを付けない。

{
  "headline_for_image": "...",
  "part1_headline": "...",
  "part1_points": ["...", "..."],
  "reusable_for_summary": ["..."],
  "audit_ledger": [
    { "source": "", "url": "", "title": "", "published_at": "",
      "verified_by": "", "decision": "採用/不採用", "reason": "" }
  ]
}
````

### 5.2 呼び出しB（フロー・総括）

呼び出しAと同じ絶対規則・ハッシュタグ規則・因果表現を再掲したうえで、以下を指示する。

````
入力として、当日の市場データ（daily_data.json）と、呼び出しAの出力
（採用したニュース、reusable_for_summary）を受け取ります。
Aが失敗している場合はニュースが空で渡されます。その場合は市場データのみで
記述し、ニュース材料が確認できなかった旨を明記してください。

- part2_flow: 2〜3本の条件付き連鎖。各連鎖は「材料 → 意識された可能性 →
  同時期に確認された値動き」の形にし、末尾を因果の限定で締める。
  地政学・マクロ、制度・政策、企業財務・市場構造のうち根拠のある系統から選ぶ。
  ニュースが無い日は、市場データ内の事実（出来高の増減、市場心理の変化、
  国内取引所とDEXの出来高動向）のみで1〜2本にとどめる。
- part2_summary: 総括。地合い・不確実性・今後の確認事項のみ。ニュースの
  再説明をしない。reusable_for_summary があれば1行だけ言及する。
  対象日の翌日が土日の場合は「翌日」ではなく「今後」「週明け」と書く。

出力形式（JSONのみ）:
{ "part2_flow": ["...", "..."], "part2_summary": "..." }
````

### 5.3 API設定

- モデル: `claude-sonnet-5`（実装時に最新の型番を要確認）
- ツール: `web_search`（呼び出しAで使用。Bでは原則不要）
- `max_tokens`: A=4000 / B=2000
- リトライ: 各2回まで。それでも失敗なら当該呼び出しを失敗として縮退へ

**前編【主要指標】**（行順固定・省略不可。取得不能でも行を残し理由を併記）

```
・ #ETH：{eth_usd}（{eth_jpy}）｜24時間比 {eth_chg}

・ドミナンス：BTC {btc_dom}｜ETH {eth_dom}
・出典・取得時刻：CoinMarketCap API／ExchangeRate-API、{retrieved_at}、USD/JPY {usd_jpy}
```

**後編【主要指標（詳細）】**

```
参考：Base上DEX全体 {dex_all}｜集計範囲・市場構造・取得時刻が異なるため、
優劣や倍率の評価は行いません
・Baseチェーン：TVL {base_tvl}（{base_tvl_jpy}）｜24時間比 {base_tvl_chg}｜

・ ETH/USDC（Base）参考APR：0.05% {apr_005}（TVL {tvl_005}／24h出来高 {vol_005}）｜
0.3% {apr_03}（TVL {tvl_03}／24h出来高 {vol_03}）※24時間データの単純年率換算
・出典・取得時刻：{sources}、{retrieved_at}
```

### 6.2 【LP運用者向けに一言】— コード生成（LLM不使用）

`daily_data.json` の `lp.pools[].change_vs_prev` と ETH の24時間比から機械的に組む。

**重要**: `change_vs_prev` は**プール単位・指標単位で独立に縮退する**。
「両プールとも全指標あり」と「丸ごと無い」の2値ではないため、下記の順で判定する。

```
[1] 参考APRの変化と要因

  1-a. プールごとに独立して文を組む（0.05% → 0.3% の順）
       各プールについて apr_change / volume_change / tvl_change の
       3指標を個別に確認する。

  1-b. 当該プールの3指標がすべて利用可能な場合
       「{プール名}の参考APRは{前日}→{当日}へ{上昇|低下}しました
        （24時間出来高 {変化率}、TVL {変化率}）。」
       主因の判定: |volume_change| > |tvl_change| なら出来高、
                   逆ならTVL、差が5ポイント未満なら主因を明示しない。

  1-c. apr_change のみ利用可能（出来高・TVLのいずれかが欠落）
       「{プール名}の参考APRは{前日}→{当日}へ{上昇|低下}しました
        （要因の内訳は一部が取得不能のため提示しません）。」

  1-d. apr_change が利用不可（当該プールの当日値または前日値が未確認）
       「{プール名}は前日比較に必要な値が取得できなかったため、
        参考APRの変化は提示できません。」

  1-e. 両プールとも 1-d に該当、または change_vs_prev 自体が存在しない
       「前日データが利用できないため、参考APRの変化は比較できません。」
       （この1文のみとし、1-a〜1-d は出力しない）

  1-f. 両プールが 1-b に該当し、かつ変化方向が同一の場合に限り、
       冒頭に「参考APRは両プールとも前日から{上昇|低下}しました。」を
       置いてから各プールの文を続けてよい（可読性のための任意圧縮）。

[2] 定型（常に挿入）
    「なお参考APRはプール全体の単純年率換算であり、個別ポジションの
     実現収益とは異なります。」

[3] ETHの方向による分岐（lp.check_message と同じ判定）
    上昇: 「ETHは24時間比{値}と上昇中のため、USDC偏り・上限側レンジ外・
           反落耐性を確認してください。」
    下落: 「ETHは24時間比{値}と下落中のため、ETH偏り・下限側レンジ外・
           下落耐性を確認してください。」
    未確認: 「ETHの24時間比が未確認のため、方向に応じた確認事項は
             提示できません。」

[4] 定型（常に挿入）
    「V3では価格が設定レンジを外れると手数料が発生しません。」

[5] 定型（常に挿入）
    「APR単独ではレンジ幅を判断できないため、出来高の持続性・レンジ外リスク・
     ILとあわせた確認が必要です。」
```

`[2][4][5]` は `change_vs_prev` の状態にかかわらず**常に出力する**（C17の対象）。
個別のポジション、レンジ、数量、金額には一切言及しない。

## 7. 縮退ラダー

| Lv | 条件 | 出力 | コミット |
|---|---|---|---|
| **L0** | A・Bとも成功 | 完全版 | する |
| **L1** | Aのみ失敗 | 数値全項目＋LP一言＋フロー・総括（市場データのみ）。ヘッドラインと主要なポイントは §7.2 の基準所定文言。図版 `summary` は前日のものを使わず §7.2 の機械生成文にする | する |
| **L2** | A・Bとも失敗 | 数値全項目＋LP一言のみ。散文欄は見出しを残して空欄。冒頭に未完了である旨を明記 | する |
| **L3** | `daily_data.json` 欠損、または C1〜C11 が1件でもFAIL | 何も出さない（既存フェイルクローズ） | しない |

**原則**: 数値とLP一言はLLMに依存しないため、L2でも必ず出力される。
本文がゼロになるのはL3のみで、その場合はデータ自体が壊れているため出さないのが正しい。

L1・L2は統合運用基準 §7 の「取得不能項目・エラー状態・限界を明示した
未完了／再取得待ちの報告」に該当する。**完成版4点としての配信ではなく、
人が仕上げるための下書きとして出力する。**

### 7.1 縮退時の定型文（統合運用基準 §3.1 の逐語引用）

L1・L2で散文が生成できない箇所には、**統合運用基準が定める文言をそのまま**使う。
台本独自の言い換えを行わない（v0.2はここで上位仕様に違反していた）。

| 箇所 | 使用する文言（逐語） |
|---|---|
| 【ヘッドライン】 | 直近24時間に暗号通貨市場との関係を確認できる主要なマクロ材料は確認できない。 |
| 【主要なポイント】 | 補足できる検証済み材料は確認できない。 |
| 【市場のフロー】 | 価格変動との関係を確認できる主要材料は確認できない。 |
| 【総括】 | （指定文言なし。確認可能な事実だけで簡潔に統合する） |

**L1の `headline_for_image`**（図版下部帯）は、前日の値を再利用せず次の書式で機械生成する。

```
{M}月{D}日（{曜}）の市況｜BTC {上昇|下落|横ばい}・ETH {上昇|下落|横ばい}
```

判定は24時間比の符号による（±0.10%未満は「横ばい」）。値が未確認の資産は
「未確認」と記す。`#` は使わず、全角40字以内に収める（C20の対象）。

### 7.2 GENERATION_STATUS.md

縮退の有無にかかわらず `outputs/{対象日}/GENERATION_STATUS.md` を毎回出力する。

```
level: L1
call_A: FAILED (HTTP 529 / retry 2回とも失敗)
call_B: OK
cryptopanic: OK (24件)
web_search: 3回

手当が必要な箇所:
  - 前編【ヘッドライン】
  - 前編【主要なポイント】

自動生成できた箇所:
  - 数値全項目（前編・後編）
  - 後編【市場のフロー】【LP運用者向けに一言】【総括】
```

## 8. (8) 本文の機械監査（C12〜C20）

`verify_post.py` を新設。1件でもFAILならコミットしない。
**縮退時は、該当箇所が空欄であることを理由にFAILさせない**（空欄は仕様）。

| ID | 検査 | 合格基準 |
|---|---|---|
| C12 | 禁止語 | 「仮想通貨」「前日比」を含まない |
| C13 | ハッシュタグ境界 | すべての `#` が行頭または半角スペース直後にあり、タグの直後が「全角コロン `：`」「半角スペース」「数値」「行末」のいずれかである。タグ直後に日本語・中黒（`・`）・スラッシュ（`/`）が続く場合はFAIL |
| C14 | 表形式の不使用 | 半角パイプ、列見出し、タブ揃え、Markdown表、HTML表を含まない |
| C15 | 見出しの存在と順序 | 前編・後編の必須見出しが規定順で存在する |
| C16 | 数値整合 | **テンプレート差し込み分**の数値が `daily_data.json` と一致する |
| C16b | 散文中の数値 | LLM生成部に `daily_data.json` 由来の数値が転記されていない（下記の限界を承知のうえでの**検知網**であり、完全な保証ではない） |
| C17 | LP免責定型文 | 6.2 の [2][4][5] の定型文が完全一致で含まれる |
| C18 | 断定表現 | 「〜が原因で」「〜により上昇」「〜を受けて下落」「〜のため上昇」「〜のため下落」「〜が牽引」を含まない |
| C19 | 監査台帳 | **L0でのみ検査**する。`audit_ledger` が1件以上あり、各件に source / url / published_at / decision / reason が揃う。L1・L2はSKIP（呼び出しAが失敗しているため台帳が原理的に存在しない） |
| C20 | 図版ヘッドライン | `headline_for_image` に `#` を含まず、全角40字以内 |

**C16bの実装と限界（明示）**

- 実装: `daily_data.json` の数値文字列（`$64,247`、`12.72%` 等）をLLM生成部から
  検索する。**長い文字列から順に照合し、前後に数字・小数点が隣接する場合は
  ヒットとみなさない**（`12.72%` が `112.72%` の一部に一致する誤爆を防ぐ）。
- 限界1（すり抜け）: `$64,247` を「64,247ドル」「約6.4万ドル」と言い換えられた
  場合は検知できない。これは**プロンプト側の絶対規則2で抑止する事項**であり、
  C16bは補助的な検知網と位置づける。完全な保証を与えるものではない。
- 限界2（誤爆）: ニュース由来の数値が市場データの数値と偶然一致した場合、
  正当な記述をFAILさせうる。発生時は `GENERATION_STATUS.md` に該当文字列を
  記録し、**人が確認して除外リストに追加できる**運用とする
  （`config/c16b_allowlist.json` を新設し、日付と文字列で例外を登録）。
